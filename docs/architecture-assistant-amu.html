Organisation du code et chaînes de traitement

Carte du code

Cette page présente l'organisation du dépôt et les deux chaînes de traitement qui le font fonctionner : celle qui transforme des documents en index, et celle qui transforme une question en réponse sourcée. Les concepts du RAG eux-mêmes sont traités par la page pédagogique. Survoler une étape d'un schéma en donne le détail.

01

Organisation du code

Le code se répartit en cinq ensembles. Les dépendances vont toutes dans le même sens : un ensemble ne connaît que ceux situés en dessous de lui. C'est ce qui permet d'utiliser l'ingestion ou la recherche seules, sans démarrer l'interface.

  1. Interface HTTP — expose les points d'entrée
  2. Génération de la réponse — assemble le prompt et interroge le modèle
  3. Recherche des passages — index vectoriel et lexical
  4. Ingestion du corpus — du document au fragment indexable
  5. Socle commun — objets partagés et configuration

Survoler un ensemble pour en connaître le contenu.

Les flèches se lisent « dépend de ». Aucune ne remonte.

02

Chaîne d'ingestion

Elle transforme une liste d'adresses en un index interrogeable. Elle s'exécute à la demande, jamais pendant qu'un utilisateur pose une question.

  1. Liste des sources
  2. Téléchargement
  3. Extraction du texte — ou mise à l'écart du document
  4. Nettoyage
  5. Découpage en fragments
  6. Vectorisation
  7. Base vectorielle
Entrée Traitement Stockage Sortie de secours

Survoler une étape pour en connaître le rôle et le fichier.

Commande : python -m assistant_amu.ingestion index

Un document illisible — un PDF scanné, par exemple — est mis à l'écart et consigné dans le rapport. Il n'interrompt jamais le traitement des autres.
03

Chaîne de réponse

Elle transforme une question en réponse sourcée. Deux sorties mènent au refus : lorsque la recherche ne remonte aucun passage, et lorsque le modèle constate que les passages fournis ne portent pas la réponse.

  1. Question posée
  2. Reformulation — seulement en conversation
  3. Vectorisation de la question
  4. Recherche des passages — ou refus si aucun
  5. Construction du prompt
  6. Modèle de langage — ou refus s'il ne trouve pas
  7. Réponse sourcée
Entrée Traitement Sortie Refus

Survoler une étape pour en connaître le rôle et le fichier.

Point d'entrée : POST /ask

La reformulation ne s'applique qu'en conversation. Sans historique, la question part telle quelle : le comportement à tour unique est reproduit à l'identique, sans appel de modèle supplémentaire.
